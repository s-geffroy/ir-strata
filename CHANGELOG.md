#### Durcissement méthodologique (rigueur interne maximale)

- **Formule critères→score réellement appliquée** : `compute_scores.derive_raw_from_criteria` calcule désormais le `raw_score` depuis les `criteria_scores` (`raw = 0.25·moy(communs) + 0.40·moy(spécifiques) + 0.35·moy(couche)`). Les **critères deviennent la source de vérité unique** ; `raw_score` est dérivé. Migration `scripts/migrate_raw_from_criteria.py` (1980 `raw_score` réalignés) et **gate bloquant** dans `validate_model.py` (critères ∈ [0,100], structure des 3 groupes, `|raw − dérivé| ≤ 0.5`). Diagnostic à l'origine : la couche globale était déjà cohérente (1/231 hors tolérance), mais 91,8 % des scores d'entités divergeaient de leurs propres critères. Dérivation mirroirée côté client (`deriveRawFromCriteria` dans `scoring.ts`). Docs `methodology/SCORING.md`, `AGGREGATION.md` et `model_metadata.json` (canonical_data_rule) mis à jour.
- **Gate de confiance** : `validate_model.py` recalcule l'`internal_score` depuis les dimensions (formule de `CONFIDENCE.md`) et **bloque** toute divergence > 0.5 ; vérifie aussi la cohérence du `label` avec les bandes documentées (2043 confiances contrôlées, 0 incohérence).
- **Gate anti-templating** : détection (warning) des preuves d'une même période partageant exactement `probative_strength` + dimensions de confiance (copier-coller). 14 lots signalés. La dette « preuves gabarit (À enrichir) » (48/48) est désormais listée dans `docs/CALIBRATION_STATUS.md`.
- **Traçabilité des révisions** : `scripts/track_revisions.py` compare les scores à un instantané (`references/scores_snapshot.json`) et journalise tout changement de `raw_score` dans `revision_log.json` (jusqu'ici vide).
- **Calibration honnête** : `docs/CALIBRATION_STATUS.md` clarifie que « sourcé » garantit un adossement à des preuves/références vérifiées, **pas** la justesse de la valeur ; le « 100 % » est explicitement « 100 % des scores _actifs_ », hors 446 rejetés pour anachronisme.
- **Fiabilité inter-codeurs** : `scripts/intercoder_reliability_test.py` (numpy + krippendorff) calcule MAE, **ICC(3,1)** et **α de Krippendorff** sur le sous-ensemble protocole (3 périodes pilotes × 7 familles × 3 couches), avec gate MAE ≤ 10 par bloc. Mode informatif tant qu'un seul codeur. Rapport `docs/methodology/INTERCODER.md`. Premier `requirements.txt` du projet (+ `pip install` dans `Dockerfile` et la CI).
- **Ancrage externe falsifiable** : `scripts/build_external_signal.py` (OpenAlex, réseau, dégradation gracieuse) construit un signal bibliométrique proxy par famille et période ; `scripts/audit_external_alignment.py` corrèle (Spearman) l'`academic_influence` du modèle au signal et **signale les périodes divergentes** (1962-79, 1979-91, 2008-14, 2014-22, 2022-26 sous le seuil 0.3). `docs/EXTERNAL_ALIGNMENT.md`.
- **Sensibilité à l'anachronisme** : `scripts/test_anachronism_sensitivity.py` recalcule la synthèse en remplaçant le rejet par un score bas (5) et compare les conclusions. Résultat : la **famille dominante reste stable** partout où une synthèse existe (choix de rejet robuste) ; le rejet ne fait que supprimer les synthèses pré-académiques. `docs/ANACHRONISM_SENSITIVITY.md`.
- **Console de codage spécialistes** : page React client-side `/coding-console` (`src/pages/coding-console/`) pour re-coder le sous-ensemble protocole **à l'aveugle** (score auteur masqué), avec calcul live du score dérivé, sauvegarde `localStorage` et export `coder_<id>.json` (déposable dans `src/data/coders/`). Protocole décrit dans `docs/methodology/SPECIALIST_VALIDATION.md` ; lien navbar.
- **Pipeline** : `generate:docs` génère les nouveaux rapports (inter-codeurs, alignement, sensibilité) ; `check:data` ajoute le gate inter-codeurs ; `data:refresh` ajoute le réalignement des critères, la construction du signal externe et la journalisation des révisions.
